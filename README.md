# 学习通巡检工具

把「登录 → 逐门课翻作业/考试/任务点 → 汇总成未完成清单」这一整套流程，固化成本地程序。
以后不用再找人对话排查，双击一下就跑完。

**「查询」只读数据**；刷课、答题交卷等改动操作全部需要你手动点按钮才发生。
所有请求都在你自己电脑上发出，账号密码不经过本程序（登录在浏览器窗口里完成），
API Key 用 Windows 用户级加密存放在本机（v3.8 起，不再以明文写进配置文件）。

> 当前版本 **v6.6**：只改了启动方式——分包启动器从 `1-一键启动.bat`
> 换成 `学习通巡检工具.exe`（无控制台窗、带图标、不怕「禁 bat」策略；
> 内部仍是拉起同目录的便携 Python）。功能、界面、用法与 v4.3.1 完全一致。
> v4.3.1：修了 v4.3 登录换账号罐后「查不到东西」的真机缺陷
> （换罐要重建常驻浏览器，旧的 Playwright 实例没收干净 → 第二次连接撞 asyncio 报错，
> 课程列表查成空；并顺带修了换罐失败回滚时偶发「文件已存在」）。
> v4.3：**全程只跑一个常驻浏览器进程**（不再每个任务各起一只）——
> 冷启动更快、更省内存，并**根治了「多任务抢 profile」**（真机「查不到东西」的根因）；

> （修了「桌面端点开自己的 Edge 被误嵌进预览、还打不了字」）。功能、界面、用法与 v4.2 完全一致。
> v4.2：**免安装包从约 240MB 瘦到约 55MB**——不再自带浏览器内核，

> 顺带把伪装浏览器身份的方式改对了（如实报告真实内核，降低被风控识别的概率）。功能、界面、用法与 v4.1 完全一致。

> **启动不再弹出任何黑色终端窗口**（后台静默运行，日志全在主窗口里）。

## 一、快速开始

### 第 1 步：安装依赖（只做一次）

双击 **`安装依赖.bat`**。
它会自动找 Python 环境并把 `playwright`、`ddddocr`、`pillow` 装好。
如果提示缺 Python，就去 <https://www.python.org/downloads/> 装一个 3.10 以上版本，安装时记得勾选 **Add to PATH**。

### 第 2 步：查询

双击 **`1-一键启动.bat`**，会打开工具自己的窗口（不是浏览器标签页）。在左边填入**账号（手机号）**和**密码**，
点 **「一键查询未完成事项」** 即可 —— 登录、扫描、出报告一条龙。

如果平台把密码登录拦下（提示密码错误，或要求点选 / 拖动验证），改用左边的
**「扫码 / 短信登录」**：会弹出一个浏览器窗口，用手机「学习通」APP 扫右侧二维码最省事。

登录成功后会话被保存到 `runtime/state.json`，**以后再查不用重新登录**。

### 第 3 步：看结果

扫描几十门课大约 2~3 分钟（课与课之间刻意留了间隔）。结果直接显示在界面右侧（作业 / 考试 / 任务点分三块展示），
同时保存到 `输出` 文件夹，点「打开最新报告」可以看完整版。

## 二、界面说明

界面是工具自己的窗口（v4.0 起用系统自带的 WebView2 渲染，没有地址栏；
窗口背后仍是一个本地控制台 `http://127.0.0.1:8765`，**只监听本机，不对外网开放**）。
v3.8 重做过：深色主题，左边一列操作区（账号 / 查询范围 / 运行中 / 模型 / 输出与退出 / 本次统计），
右边是「查询结果」「运行日志」「**预览**」三个页签；结果按**台账**排（表格吸顶、每门课一行、点开看章节），
操作说明收在底部可展开的区域里。

**「预览」页签（v4.1 起）**：自动化浏览器**直接嵌在这一页里**——扫码登录、答题交卷、
「去完成」打开的作业页，全在这里看得见、点得着。有浏览器窗口时页签旁标**「（进行中）」**；
没有浏览器窗口时这一页显示**「无内容」**。不想看它就不点这个页签，一切照旧。

| 区域 / 按钮 | 作用 |
|---|---|
| **账号 / 密码** | 填学习通手机号与密码，配合「一键查询」使用 |
| 记住账号 | 只记手机号，不记密码 |
| 下钻到章节 | 勾选后未完成任务点会展开到具体章节（默认勾选） |
| **一键查询未完成事项** | 登录（如需要）+ 全量扫描，一步到位（主力功能） |
| **扫码 / 短信登录** | 弹窗内扫码或短信验证码登录；**想换账号也用它**——每次点击都是全新登录，不会自动登回上一个账号 |
| **只查最近 N 门课** | 填个数字，直接只查最近学过的 N 门——**不用先获取课程列表** |
| **获取课程列表** | 只读课程名单（约 10 秒），读完可以勾选要查哪几门 |
| **置顶已选的课** | 把勾上的课排到列表最上面并加分隔线，方便核对（不影响查询范围） |
| **模型** | 选平台、填地址 / 模型名 / API Key，保存与测试连接（详见下文） |
| 打开最新报告 / 打开输出文件夹 | 用系统默认程序打开报告 / 定位到 `输出` 目录 |
| **退出程序（释放端口）** | 结束后台进程 |

顶栏右侧有两个常驻指示：左边是**状态**（空闲 / 运行中 / 已完成），右边是**「本机会话」**
——随时告诉你工具现在用的是哪个账号（v3.7 起）。

扫描在后台线程里跑，**把窗口最小化、关掉屏幕都不影响**（扫描会继续跑完）。

### 只想查其中几门课

不必每次都把所有课程扫一遍。有两种做法，按需要挑：

**做法 A —— 只查最近 N 门（最快）**

在左侧「**只查最近 N 门课**」里填个数字，直接点「一键查询」。
**不用先获取课程列表**，也省掉一次登录往返。顺序用的是学习通默认的「最近学习过的在前」，
所以取前 N 门就是最近学过的 N 门。只想快速看一眼最近的课、或先试试工具好不好用，用这个。
（输入框里按回车等于点查询。）

**做法 B —— 指定具体某几门（精确）**

1. 点 **「获取课程列表」**（约 10 秒，只读名单，不抓任何作业）
2. 左侧出现课程清单，**勾选**你要查的课（**勾上就生效**，不用再点确认）
3. 点「一键查询」，**只扫你勾的那几门**

两者同时用时**以勾选为准**，上方填的 N 会被忽略（界面会明确提示一句）。

几个细节：

- 做法 A 填的数 ≥ 课程总数时，按「查全部」处理，不标注范围（结果上本来就等价）。
- **一门都不勾、也没填 N = 照旧查全部**，所以不用这两个功能也完全不影响原来的用法。
- 课程面板上方有 **筛选框**（输「英语」就只剩名字带英语的），配合「全选 / 清空」可以批量操作——
  这两个按钮**只作用于当前筛选出来的可见项**，所以「搜『英语』→ 全选」就是选中所有英语课。
- 勾选后**没勾的课程会被压暗**，按钮右边直接显示「已选中 N 门课」，一眼能看出这次查哪几门。
  改动勾选时这两处立刻跟着变，不需要点任何按钮。
- **「置顶已选的课」按钮**：把已勾选的课排到列表最上面，中间插一条
  `以下 N 门未勾选（本次不查）` 的分隔线，方便核对完再点查询。它**不影响查询范围**——
  勾选本来就已生效，这个按钮只改变显示顺序。改了勾选之后分隔线会自动撤掉（数量已过期）。
  和做法 A 的结果一样，区别是**你能看见勾了哪几门**、还能在此基础上手动加减。
  只想快就不填它，想看得清楚就用它。
- 只查了一部分课的报告会**明确标注范围**，而且会区分是哪种：
  勾选的写 `⚠️ 本次只检查了你勾选的 5 门课程（账号共 37 门）`，
  用做法 A 的写 `⚠️ 本次只检查了最近学习的 5 门课程（账号共 37 门）`。
  这句是必需的——否则你看到清单里没有别的课，很容易误以为都完成了，而事实是根本没查。
- 如果勾的课在当前名单里已经不存在（课程被删或改名），会**跳过并告警**；
  若一门都匹配不上，会直接报错而不是给你一份空报告。
- 「获取课程列表」是一次独立任务，**不支持暂停/停止**（它只有十来秒），
  这段时间暂停和停止按钮是灰的。

### 怎么中途暂停 / 停止

一轮全量扫描约 2~3 分钟，中途想缓一缓或者不扫了，随时可以：

| 按钮 | 行为 |
|---|---|
| **暂停 / 继续** | 停在当前这门课结束时，进度全部保留；点继续，从下一门接着扫 |
| **停止本次查询** | 结束扫描，**已扫完的部分照常出报告**，报告里标注「中止扫描，只检查了 N/M 门课」 |

两个动作都在**课程边界**生效，所以点下去之后最多等约一门课（10 秒左右）才真正停住——
这样不会把正在进行的网络请求撕断。只有扫描运行中，这两个按钮才可点。

实现上，扫描器（`chaoxing_scanner.py`）完全不知道界面的存在，它只在每门课开头调用一次
`checkpoint()`；界面通过 `set_control_hook(fn)` 注入回调，在回调里阻塞等 `PAUSE` 事件，
或用返回 `False` 表示中止。**CLI 模式不注入钩子，行为与以前完全一致。**

> **停止后有几秒不能开始新查询，这是正常的。**
> 这几秒在把结果写成报告，状态栏会显示「收尾中 · 正在生成报告」。
> 此时点查询会被明确拒绝并提示「上一个任务还在收尾」——等状态变回「已完成」再点即可。
> （早期版本在这里不给任何反馈，界面上看起来就像按钮失灵了，实际是后端回了 `409 busy` 被前端忽略。）

收尾阶段由 `scan()` 在生成报告前调用 `checkpoint('reporting')` 通知界面，
`_control_hook` 收到后把 `STATE['phase']` 置为 `finishing`，poll 接口再带给前端。

### 刷视频：把未完成的任务点视频挂后台（v2.7 起）

查询结果「未完成任务点」一节顶部有一条**工具条**，每门课的折叠条右侧有一个
**「选中」勾选框**：勾上想刷的课（勾上即生效），再点工具条上的
**「刷选中的课的视频」** 即可。倍速下拉、「熄屏」、「刷完自动关机」也在这条工具条上。

| 行为 | 说明 |
|---|---|
| 播放方式 | 在后台浏览器里**真实播放**：静音，倍速在工具条的下拉框选（1.0 / 1.25 / 1.5 / 2.0，默认 1.25，选择会被记住），实际在所选档与相邻官方档之间随机、约三分之一概率中途换挡，并周期性模拟鼠标活动；开刷后浏览器自动收进主窗口的「预览」页签（不挡屏幕、不影响播放）；播到片尾为止 |
| 完成判定 | 播放器自己发心跳，平台看到的就是一次真实观看；章节列表里对应节点会翻绿 |
| 只刷视频 | 测验、作业、讨论等其它任务点**不会替你自动完成** |
| 暂停 / 停止 | 与查询共用左侧同一对按钮：暂停会把当前视频一起暂停；停止保留已刷完的部分 |
| 熄屏 | 工具条上的「熄屏」= 立刻强制关闭显示器，任务照常在后台跑；动下鼠标或按任意键点亮。万一黑屏唤不醒（个别显卡驱动），按 `Win+Ctrl+Shift+B` 重置显卡驱动即可 |
| 自动关机 | 勾上「刷完自动关机」：只有在**正常跑完**时才关机，留 60 秒缓冲（`shutdown /a` 可取消）；手动停止、出错、未登录都不关 |
| 进度 | 日志面板实时显示「第几门课 · 哪个节点 · 播放到几分几秒」 |

几点实话：

- **刷视频不是瞬时的**。视频有多长就要播多久（默认 1.25 倍速），一门课 10 个 20 分钟的
  视频大约要 130 分钟。适合挂机，不适合救急。连刷 6 个还会自动歇 30 秒左右。
- 偶尔视频会在中途**自动暂停**（平台插入的互动点），工具会自动点继续；
  视频卡住会先**原地重试一次**（v3.3 起），仍不行才跳过并在日志里说明，需要你手动看那一个。
- 请求密度比查询高，**不建议一次勾十几门课连着刷**；工具已在课程之间留了间隔，
  但使用频率自己把握，账号安全第一。
- 播放进度日志默认每 5 分钟报一次，每门课刷完立即汇报一次汇总。

### 大模型答题：自动做章节任务点里的作业（v2.9 起，v3.8 重做设置，v3.9 加视觉模型）

前置：在网页左侧 **「模型」** 卡片里点四下——

1. **平台**下拉选一个（DeepSeek / OpenAI / 通义千问 / Moonshot / 智谱 GLM / 自定义）。
   选完**接口地址与模型名会自动带出来**，不用去翻各家文档。
2. 接口地址：任何 OpenAI 兼容接口都能用。填到 `/v1` 为止、或直接粘完整地址都认。
   别把浏览器地址栏里带 `#` / `?` 的网址粘进来——那不是接口地址，程序会当场说清原因。
3. **API Key**：粘进去。已保存的 Key 不回显在页面上（只显示 `sk-abc…0xyz` 打码串）。
4. 点 **「保存」**，再点 **「测试连接」**：拿你填的信息真调一次模型，通了把它回的话显示出来。
   缺哪样、哪里错（地址不对 / Key 无效 / 欠费 / 限流 / 超时）都用中文分开讲清楚。

「测试连接」只验证不落盘；垃圾桶按钮是**「清除 Key」**（删掉本机保存的那把）。
Key 在 Windows 上用系统自带的用户级加密（DPAPI）存到 `runtime/llm_key.dpapi`，
`config.json` 里不留明文；换电脑或换 Windows 用户后需重填一次。
费用走你自己的 Key 按量计费，一份选择题作业通常只花几分钱。

#### 视觉模型（可选，v3.9 起）：让模型「亲眼看」图片题 / 公式题

超星的数学公式常常是**图片或 MathML 渲染**的，纯文字提取拿到的往往是空白或乱码——
这类题用纯文本模型必然答不上。**「模型」卡片里多了一个可折叠的「视觉模型（可选）」**，
填一个多模态模型（通义千问 `qwen-vl-max`、智谱 `glm-4v-flash`、OpenAI `gpt-4o` 等），
工具就会在**需要看图的题上截图**喂给它，逐题对着图作答。

- 怎么配：展开那块折叠区 → 选平台（自动带出该平台的视觉型号）→ 粘 Key → 「保存」。
  三项（地址 / 模型名 / Key）齐了才生效。
- **留空 = 不启用**，完全按原来的纯文本答题走，行为一点不变。
- 启用范围刻意收窄：只对**主观题（填空 / 简答）**和**题干里带图片 / 公式**的题调用，
  客观选择题继续用文本模型——**不让每道选择题都花这份钱**。
- 与主模型**各存各的**：地址、模型名、Key 都独立（Key 加密存在
  `runtime/llm_vision_key.dpapi`）。两家用同一个 Key 也行，填一样的即可。
- 选了 DeepSeek 这类**暂无视觉模型**的平台，界面会当场说破并让你换一家，
  而不是让你去手填一个并不存在的模型名。

用法：在「未完成任务点」里**勾选课程**（整门课或展开后只勾某几节），然后二选一：

| 按钮 | 行为 |
|---|---|
| 做作业（点开下拉二选一） | **做作业并暂存**：大模型答题后只存平台草稿不交卷，人工审查后自己交；**做作业并提交**：走平台**完整提交流程**（等价于你本人点「提交」并确认） |
| 刷课+刷题 | 先把勾选课程的未完成视频刷完，再自动答题交卷，一键两连 |

另外，「未完成作业」清单里**每行右边还有一个「做作业」按钮**（同样点开下拉二选一）：
只做你点中的那一份，判别规则与上面的按钮完全一致（要上传附件的题整份跳过、题干读不出来的也跳过）。
有题模型没答上时不会硬交：答上的那几道会先暂存到平台（见下「安全阀」）。

> v3.9 起，刷题 / 刷课 / 刷视频这类任务**一结束就会自动把界面收回「查询结果」页，
> 并用你左侧当前的勾选重跑一次查询**——刚做完的作业会从清单里消失，不用再手动点一次。
> 运行日志不会被这次自动刷新清掉，你随时可以切回去看过程。
>
> 两条边界：
> ① 勾了「刷完自动关机」时**不重跑**（机器马上要关，再挂一次 1~2 分钟的全量扫描
> 只会在关机倒计时里被掐断）；结果区保持原样，不会留下「正在后台刷…」那种假象。
> ② 任务如果产出了**「交卷结果」面板（做作业并交卷 / 刷课+刷题），就以面板为准、不重跑**
> ——面板里那个「重新核实未确认的」按钮，被刷新冲掉就找不回来了。

交卷后会自动**重开作业卡核实**平台是否收下；显示「⚠ 已发出·待平台确认」的份，
可用结果面板里的 **「重新核实未确认的（N 份）」** 按钮隔几分钟再核（平台批阅偶尔
延迟几分钟），核实到已批阅就自动翻案成「此前已交」。

安全阀（自动答题的底线）：

- 自动答**单选 / 多选 / 判断 / 填空 / 简答**（客观题选字母，填空简答由大模型写文本）
- **多空填空题按空的前后顺序逐个填**：「___、___、___」三个空就分别填三个答案，
  不会把一串答案灌进同一个空
- **要上传附件的作业（实验报告类）整份跳过**，不保存——保存会把任务点锁成完成，
  你就没法再上传自己的报告了；跑完后汇总会点名列出哪些课的哪些份需要你手动做。
  题干里说「提交/上传报告、文件、作品、附件」、或题里有文件上传控件、
  或题干压根读不出来（平台字体反爬）的，都按这一类处理
- 大模型**没把握的题（返回 ?）、或答非所问地讲「这题该怎么操作」的 → 整份都不交卷**，
  日志里列出是哪几题。宁可留给你自己做，也不往卷子上填一个错的答案。
  但答上的那几道不会白做：工具会把它们**分批暂存到平台**（每几道存一次），
  面板上标「已暂存 · 待补完再交」——打开作业网址补完剩下的题再点提交即可，
  先前暂存的答案还在。只有「一道都没答上」才会整份不碰
- 交卷那一步如果平台侧没走通（提交函数报错、或请求压根没发出去），
  工具也会先把已填的答案暂存下来，避免「做完了、平台上什么都没有」
- 提交动作调的是平台自己的交卷函数，等价于你本人点「提交」
- CLI 等价命令：`python chaoxing_scanner.py answer 课程名`（直接交卷）

几句实话：

- 大模型做**大学英语、思政、通识类**题目准确率很高，**专业课**看题目，
  没把握的题工具会自动放弃而不是硬答——宁可留给你手动做，也不污染成绩
- 想核对答案：做完后去学习通打开对应章节的作业即可看到已填内容
- 题目分页的作业（一页 10 题）目前按单页处理，遇到会提示跳过

### 怎么退出

| 方式 | 效果 |
|---|---|
| 窗口左下角点「退出程序」 | 推荐。先让正在跑的任务收尾，再结束进程 |
| 直接关掉工具窗口 | 等效；但任务正在跑时这一次点击会被拦下（见下） |

v4.1 起**双击启动不会再弹出黑色终端窗口**——程序完全在后台静默运行，所有日志都在
主窗口的「运行日志」页签里，所以也不存在「关错命令行窗口」这回事了。

**任务运行中点 × 是关不掉的**：窗口不会关闭，并在日志里说明原因。这是故意的——
直接退会把刷到一半的进度丢在平台那儿。要退出请先点「停止」，或走「退出程序」。

v4.0 起窗口一关程序就结束了，不会像早期的网页版那样留在后台占端口。

实现上，`/api/quit` 先回包再异步调用 `httpd.shutdown()`（`shutdown()` 必须由 `serve_forever()` 之外的线程调用，
且不能先关连接、否则浏览器只会看到一个「网络错误」）。

## 三、输出文件

都在 `输出` 文件夹里：

| 文件 | 说明 |
|---|---|
| `学习通未完成清单.md` | 最新一次的报告（每次覆盖，方便直接看） |
| `学习通未完成清单_日期_时间.md` | 带时间戳的历史版本，不覆盖 |
| `学习通未完成清单_日期_时间.csv` | 表格版，可直接拖进 Excel / WPS |
| `记录/日期_时间.json` | 机器可读快照，用于和上次对比 |

报告分四部分：

1. **未完成作业** —— 带课程、作业名、状态、剩余时间，还有**直达链接**（点一下直接跳去做题）
2. **未完成考试**
3. **未完成任务点** —— 章节视频/资料的完成进度
4. **附录：全部课程状态总览** —— 37 门课逐一的作业/考试/任务点状态

另外每次扫描结束会自动和上一次快照对比，在日志里打印「新增了哪些、消失了哪些」，方便盯变化。

### 关于「未完成」的口径

学习通的作业状态有好几种：`未交`、`已完成`、`待批阅`、`已提交`、`已互评`、`待互评`。

**只有「未交」才是真正需要你动手的**；`待批阅`（老师还没改）、`待互评`（互评环节还没开）这些平台自己都算作已完成。
本工具按平台口径统计 —— 这也是为什么报告里的「未完成数」总能和课程页上「已完成/总数」的缺口对上。

## 四、命令行用法（可选）

不想用界面的话，直接在项目目录下执行：

```bat
python chaoxing_scanner.py doctor            :: 环境自检
python chaoxing_scanner.py selftest          :: 检测学习通是否改版（逐层验证解析规则）
python chaoxing_scanner.py login             :: 可见窗口登录
python chaoxing_scanner.py login --auto      :: 短信验证码全自动登录
python chaoxing_scanner.py list              :: 只列出课程名录（约 10 秒）
python chaoxing_scanner.py scan              :: 全量扫描
python chaoxing_scanner.py scan --limit 3    :: 只扫最近 3 门（最近学习过的在前）
python chaoxing_scanner.py scan --only 1001:c1,1002:c2   :: 只扫指定课程
python chaoxing_scanner.py scan --headed     :: 扫描时显示浏览器窗口（排查问题用）
python chaoxing_scanner.py brush 高等数学     :: 刷某门课未完成的任务点视频（名称部分匹配）
python chaoxing_scanner.py brush 高等数学 大学英语 --rate 1.5
python chaoxing_scanner.py desktop           :: 打开桌面窗口（默认入口）
python chaoxing_scanner.py gui               :: 打开网页控制台（备用）
```

`--only` 的值就是 `list` 打印出来的方括号里那串（`courseId:classId`），逗号分隔。
它优先于 `--limit`。

也可以直接双击 `首次登录.bat` / `检查环境.bat`。

**定时跑**：配合 Windows 任务计划程序，让它每天早上自动执行
`python chaoxing_scanner.py scan --no-open`，报告就会静静躺在 `输出` 里。

## 五、配置文件 `config.json`

首次运行会自动生成，需要的话手动改：

```json
{
  "chrome_path": "",        // 浏览器内核路径，留空 = 自动探测 / 首次自动下载
  "headless": false,        // 扫描时是否无头（默认 false，有头更安全）
  "course_delay": 3.0,      // 每门课之间的间隔秒数；正常就按它走，撞风控自动翻倍
  "brush_rate": 1.25,       // 刷视频倍速（界面下拉可选 1/1.25/1.5/2；实际在所选档与相邻官方档间随机）
  "auto_captcha": false,    // 验证码是否自动识别（默认 false，人工点选更安全）
  "brush_rest_every": 6,    // 每连刷 6 个视频歇一次（0 = 不歇）
  "brush_rest_seconds": 30, // 歇多久（±40% 随机），模拟人离开一下
  "brush_retry": 1,         // 单个视频卡住/超时后原地重试次数（0 = 不重试）
  "brush_minimize": true,   // 开刷后浏览器自动收进主窗口「预览」页签（不挡屏幕，不影响播放）
  "page_wait": 3.0,         // 页面加载后的额外等待秒数，网络慢就调大
  "max_courses": 0,         // 0 = 全部
  "open_report": true,      // 生成后自动打开报告
  "cpi": "",                // 学习通个人参数，自动获取
  "user_agent": "",         // 留空 = 按内核版本自动生成
  "llm_platform": "",       // 模型平台（deepseek / openai / qwen / moonshot / glm / custom）
  "llm_url": "",            // 接口地址：填 base、填到 /v1、或完整地址都认
  "llm_model": "",          // 模型名，如 deepseek-chat
  "llm_key": "",            // 见下方说明：Windows 上默认不在这里存明文
  "llm_vision_platform": "", // 视觉模型（可选，v3.9 起）：与上面那套完全独立
  "llm_vision_url": "",     // 留空 = 不启用视觉，仍按纯文本答题
  "llm_vision_model": "",   // 如 qwen-vl-max / glm-4v-flash / gpt-4o
  "llm_vision_key": ""      // 同样加密存 runtime/llm_vision_key.dpapi
}
```

**关于 `llm_key`（v3.8 起）**：Windows 上 API Key 走系统自带的用户级加密
（DPAPI），落在 `runtime/llm_key.dpapi`，`config.json` 里的 `llm_key` 保持为空。
加密与「当前 Windows 用户」绑定，文件拷到别的机器 / 换个用户都解不开，
程序会提示重新填写而不是假装可用。非 Windows（或 DPAPI 不可用）时才回落到
明文存放，并在日志里说明。老版本留在 `config.json` 里的明文 Key 会在第一次
读取时自动迁进加密文件、同时把明文撤掉。

**关于视觉模型的 Key（v3.9 起）**：同一套加密，但**单独一份文件**
（`runtime/llm_vision_key.dpapi`）。两个模型可能落在不同平台、各用各的 Key，
共用一份必然互相覆盖，所以刻意分成两份，互不影响。

## 六、学习通改版了怎么办（兼容性体检）

学习通是第三方平台，页面结构随时可能变。与其等一次全量扫描跑完才发现结果是空的，
不如先用体检把「工具依赖的每一层」逐层探一遍。

> 这个体检是**命令行功能，界面上不放入口**（普通使用者用不到，界面保持简洁）。
> 排查问题、或用户反馈「学习通更新后查不出东西」时，在命令行跑：

```bat
python chaoxing_scanner.py selftest
```

约半分钟，全程只读。它会依次验证：

| 层 | 检查项 | 失效后果 |
|---|---|---|
| L0 | 本地运行环境（内核 / 验证码识别） | 与平台无关，缺失只影响速度与自动登录 |
| L1 | 登录会话是否还有效 | 失效 → 重新登录即可，不是改版问题 |
| L2 | 课程列表能否解析（`a[href*=stucoursemiddle]`） | **最致命**：什么都查不到 |
| L3 | 卡片上的任务点进度 `x/y`（`.l-txt`） | 卡片概览丢失，「是否有缺口」判断失效 |
| L4 | 课程页左侧导航 `li[dataname]` | 作业/考试/章节的入口，读不到等于全抓不到 |
| L5 | 作业列表能否打开并解析（`/work/list`） | **核心功能**：作业漏查或全丢 |
| L6 | 考试列表（构造式 URL） | 考试漏查 |
| L7 | 章节下钻（`.chapter_item`） | 只影响任务点明细，作业/考试不受影响 |

结论分三档：✅ 通过 / ⚠️ 基本通过（有需留意项）/ ❌ 未通过（列出具体哪层断了）。
报告写到 `输出/兼容性体检_日期.md`，把它发给助手就能直接定位要改哪段解析规则。

**所以答案是**：学习通改版不等于工具报废 —— 大概率只有某一层需要改十几行选择器，
体检就是为了把「哪一层」变成确定的信息，而不是靠猜。

## 七、账号安全与防检测（v3.2 / v3.3 / v3.7 / v3.8 / v3.9）

工具的全部操作都在**真实浏览器**里以你的登录态进行——不伪造请求、不碰协议漏洞。
在这个前提下，v3.2 / v3.3 把「看起来像机器人」的地方逐项抹平：

**本机凭据（v3.8 / v3.9）**

- API Key 用 Windows 自带的**用户级加密**（DPAPI）存到 `runtime/llm_key.dpapi`，
  明文不再落在 `config.json` 里；文件被拷到别的电脑或别的 Windows 用户下都解不开。
- 视觉模型的 Key 走同一套加密，但**单独一份文件**
  （`runtime/llm_vision_key.dpapi`）——两个模型可能落在不同平台、各用各的 Key，
  共用一份必然互相覆盖。
- 页面上不回显已保存的 Key（只显示打码串），「测试连接」只验证不落盘。
- 登录会话（cookie）与浏览器痕迹仍在 `runtime/` 里，从不随分发包发出
  （打包流程强制排除 `runtime/`，并在出包前扫描 API Key 形态的字符串）。

**登录与账号隔离**

- 每次在界面里重新登录，都会启用一个**全新的浏览器环境**（旧会话罐自动归档保留一份），
  不把上一次登录的痕迹带进新会话。
- 多账号轮流用时，各账号的会话相互隔离，不会出现「A 号的 cookie 带进了 B 号」。
- **v3.7 修了一个会让这条承诺失效的缺陷**：此前工具只判断「本机有没有登录」，
  不判断「登的是谁」。本机还躺着一份可用会话时，你在界面填的账号密码会被**忽略**，
  直接拿旧会话去查——于是「用 A 账号登录，进去却是 B 账号」，而之后的刷课、
  交卷也会算到 B 头上（不可撤销）。
  现在工具会把「这份会话属于哪个账号」记在 `runtime/identity.json`，填账号密码时
  先比对：**一致**就直接复用（不必重登）；**不一致**就改登你填的账号（旧会话归档，
  不丢）；**不记得是哪个**（如上次是扫码登录）就当作不可信，照样重新登录一次。
  界面左侧常驻一行「本机会话」，随时写明当前在用哪个账号——不再有静默的错误身份。

**浏览器指纹**

- 抹除自动化标记（`navigator.webdriver`），补齐缺失的浏览器特征，
  让权限查询等接口的行为与正常浏览器一致。
- 默认**有头模式**运行（扫描时窗口会弹到前台）：无头 Chrome 有一堆可检测特征
  （插件为空、字体异常等），有头模式的行为与真人无差——账号安全优先于后台安静。

**行为节奏**

- 课间间隔、轮询节奏、翻页滚动步长全部带**随机抖动**，不再是精确的固定值。
- 刷视频倍速在界面下拉选择（1.0 / 1.25 / 1.5 / 2.0，默认 1.25），
  实际在所选档与相邻官方档之间随机、约三分之一概率中途换挡，
  并周期性模拟鼠标活动；连刷若干个视频自动歇一会儿（时长随机），像人离开座位。
  只用官方档位是刻意的：随意的小数值倍速（如 1.4）会被平台拨回去、
  工具再拨回来，两边打架就是播放中频繁的约 1 秒小暂停。
- 大模型答题把「开卷—做题—检查—提交」拆成多步，步骤之间留人类级别的间隔。

**出错时的自保**

- 点选验证码默认**留给你手点**（弹验证码本身就说明被风控关注了，
  OCR 点错反而加重标记；确要自动识别改 `config.json` 的 `auto_captcha`）。
- 视频卡住先原地重试一次再放弃；播放器状态连续失联会快速判定并走重试链，不空耗。
- 撞风控自动冷却、课间自动翻倍，连续失败主动中止（详见下一节常见问题）。

以上都是**降低风险**而非消除风险：请控制使用频率，不要整夜连刷，
账号安全的第一责任人始终是你自己。

## 八、常见问题

**Q：提示「本地没有可用登录态，请先执行 login」**
登录态过期了。点界面上的「扫码 / 短信登录」重新登一次即可。
学习通的会话 cookie 是会话级的，浏览器被强杀或隔较久就会掉，属正常现象。

**Q：登录进去的账号，跟我输入的不是同一个？**
v3.7 已修。旧版本只认「本机有没有登录」，不认「登的是谁」——本机存着别的账号
的会话时，你填的账号密码会被忽略、直接拿旧会话去查（刷课、交卷也会算到那个
账号头上）。升级后填账号密码 → 工具先比对本机会话属于谁，不一致就改登你填的
这个；界面左侧「本机会话」那行会写明当前在用哪个账号。
正卡在这个状态的话，直接点「扫码 / 短信登录」重登一次也能解脱。

**Q：登录时跳出「请依次点击『X』『Y』『Z』」验证码**
在可见窗口里手动点，最省事。
如果用的是 `login --auto` 全自动模式：程序会先尝试自动识别，**识别不全时会自动打开一张带红框编号的图**，
你按提示顺序输入编号（比如 `3 1 4`）回车，程序替你点击 —— 大约 5 秒。
（实测这类书法体汉字机器识别率只有一半出头，所以留了这条兜底路径。）

**Q：第一次扫描时它在下什么东西？**
**v4.2 起一般什么都不用下**：工具直接用你电脑上已装的 Edge / Chrome 跑
（Win10/11 自带 Edge，几乎必然命中）。
只有在系统里 Edge、Chrome 都没有时，才会自动下载一份 Chrome for Testing
内核（约 150MB，只下一次，存 `runtime/chrome` 后一直复用）。

**Q：学习通更新了，这工具还适用吗？**
命令行跑 `python chaoxing_scanner.py selftest` 做一次体检（约半分钟，只读），
它会逐层告诉你本工具依赖的页面结构是否还有效、断在哪一层、后果是什么。详见第六节。
体检通过却仍查不出结果，通常是登录过期（新解压的目录必须先登录一次）
或那几门课本身没有作业。

**Q：某几门课显示「无作业模块」**
不是漏抓。有些课（比如纯考试课、AI 助教课）本身就没有「作业」这个栏目，
程序会读课程页左侧导航来判定，导航里没有「作业」才会这么标。

**Q：有的课显示「⚠ 页面未加载」**
说明那几门课的页面当时没打开成功（网络抖动、平台临时拦截都会这样），
**它们的作业/考试结果是「没查到」而不是「没有」**。程序会自动重试一次
（撞了平台风控会先冷却 20 秒再试），重试仍失败就在报告和界面里明确标出来。
遇到这种情况稍后重新查询即可。

**Q：连续多门课都「页面未加载」怎么办**
这是触发平台风控了。程序现在会自我保护：连续 3 门失败就全局长冷却 45 秒
（还不行再冷却 90 秒），冷却期间点「停止」立即生效；两次冷却后仍连挂就
**主动中止扫描**，避免越撞越死。撞过风控后，本次扫描的课间间隔会全程
保持 2.5 秒不再提速。正确姿势：等 10 分钟以上再查，或先只勾选几门重要的课分批查。

**Q：扫描很慢 / 卡住**
默认每门课 3 秒（`config.json` 的 `course_delay`）。几十门课两三分钟属正常；
明显超出先看网络连通性，再考虑调大 `page_wait`（它是每页的等待上限，
页面就绪就走，填大只会让慢的时候多等）。课间间隔是自适应的：
正常按 `course_delay` 走，哪门课页面出过状况就自动翻倍拉长，保护会话不被风控。

**Q：任务点能细到什么程度？**
现在会**自动下钻到章节**。只要某门课的任务点没做完，报告里就会列出该课每一章的
「待完成任务点」数量（例如「1.1 系统概述　待完成 2」），不用再自己点进去数。
这个下钻只对有缺口的课程执行，所以几乎不增加整体扫描时间。
（判定依据：章节节点带 `.catalog_jindu.catalog_tishi120` 即为未完成，
其中 `.catalog_points_yi` 的数字就是待完成数；已完成的节点没有这个元素。）

**Q：「刷视频」是什么原理？会不会封号？**
它在后台浏览器里**真实播放**视频（静音，倍速界面可选，实际在相邻官方档位间随机、中途换挡），
播放器自己发心跳，平台看到的就是一次正常观看——没有伪造任何请求。
倍速只提供播放器自带的官方档位（1.0 / 1.25 / 1.5 / 2.0）——非官方档位会被平台
拨回去造成频繁小暂停；行为节奏带随机抖动、周期性模拟鼠标活动
（详见「账号安全与防检测」一节）。风险与正常看视频相同，但**请求密度比手动观看高**，
不建议一次勾太多门课连着刷；刷视频时账号同时在别处登录看视频，也可能相互顶掉，
自己安排好时间。

**Q：为什么有的视频刷不动？**
三种情况会跳过并在日志说明：① 视频中途有**弹题**（同一位置反复暂停）；
② 那个任务是测验/作业，不是视频——工具不替你答题；
③ 视频超长，超过了超时保护上限。这些都需要你手动看一遍。

## 十、原理（给好奇的人）

抓取链路全部走的是学习通网页自己用的接口，没有破解任何加密：

1. **课程列表** —— 打开 `i.chaoxing.com/base`，从内嵌 iframe 里取到 `mooc2-ans.chaoxing.com/visit/interaction`，
   滚动触发懒加载后，从课程卡片 `div.learnCourse` 里读出课程名、`courseId`、`classId`、任务点进度。
2. **作业列表** —— 每门课打开 `mooc1.chaoxing.com/visit/stucoursemiddle?...`，
   点左侧「作业」导航，读出它加载的 `mooc2/work/list` iframe 地址
   （这个地址里的 `enc`、`stuenc` 是**点击时动态生成**的，没法跨课程复用，所以必须逐个点）。
   列表每页 12 条，用 `.xl-nextPage` 翻页直到没有下一页，然后从 `.right-content` 里提取
   标题 / 状态 / 剩余时间 / 直达链接。
3. **考试列表** —— `mooc1.chaoxing.com/exam-ans/mooc2/exam/exam-list?courseid=..&clazzid=..&cpi=..`，
   这个地址可以直接构造，不用 `enc`。结构与作业列表一致。
4. **登录态** —— 登录后用 Playwright 的 `storage_state` 把 cookie（含会话级 cookie）整体导出，
   下次启动时注入回去，就能免登录。

### 为什么不用 agent-browser

之前那套排查用的是 `agent-browser` CLI。它的守护进程会随发起它的 shell 一起被回收，
导致「`open` 成功但 `get url` 变 about:blank」、登录态莫名丢失；而且 `| head` 这类管道会把它 SIGTERM 掉。
换成 Playwright 之后，浏览器生命周期完全在 Python 进程内，
上述问题从根上消失了 —— 更少组件，更少坑。

## 十一、分发给别人用（免安装包）

本项目可以打包成一个**解压即用**的压缩包（**v4.2 起约 55MB**）：同学拿到后不用装
Python、不用联网下内核，解压双击就能用，账号密码只在他自己电脑上使用。

构建方式（在项目目录下执行）：

```bash
bash build/build_all.sh     # 组装 build/pkg：下载便携 Python + 装依赖
python build/package.py     # 压缩成「学习通巡检工具.zip」
```

> v4.2 起**不再把浏览器内核打进包里**（原 chrome/ 约 190MB），运行时改用目标机
> 上已装的 Edge / Chrome（Win10/11 预装 Edge）；两者皆无才在首次运行时联网下载兜底。

包内结构：

```
学习通巡检工具/
├── 学习通巡检工具.exe     ← 双击启动（原生无控制台程序，带图标）
├── 先看使用说明!!.txt     ← 一句话提示：先解压，再双击 exe
├── 使用说明.txt
├── 最新版下载地址.txt
├── app/                  ← 程序本体
│   ├── chaoxing_scanner.py
│   ├── webui.py
│   ├── captcha_solver.py
│   └── config.json       ← 已清掉个人 cpi / API Key
└── python/               ← 便携 Python 3.13 + playwright + pillow
```

> 启动器 v6.6 起从 `.bat` 换成了 `.exe`：源码见 `build/launcher/launcher.cs`，
> 由 `build/mk_extras.py` 调用系统自带 `csc.exe` 编译（产物仅约 28KB，
> 仍是去拉起同目录的 `python\pythonw.exe app\chaoxing_scanner.py desktop`）。
> 换 exe 的好处：双击不再闪黑色控制台窗、有图标、也不怕个别机器
> 「禁止运行 .bat」的安全策略。

> v4.2 起包里**不再有 `chrome/`**（原约 390MB）——运行时用目标机系统上的
> Edge / Chrome；两者皆无才首次联网下载一份内核到 `app/runtime/chrome/`。

⚠️ **分发前务必检查**：`app/runtime/` 里存的是**你自己的登录态**（`state.json`、
`identity.json`）和**加密后的 API Key**（`llm_key.dpapi`），`app/输出/` 里是你的报告，
都不应打包给别人。`build_all.sh` 已自动清理这两处，`package.py` 出包前还会再扫一遍
敏感串（API Key 形态、手机号、登录态），但手动打包时请留意。

界面上的「账号 / 密码」两个输入框就是给别人用的：
填完点「一键查询」即可；若平台拦下密码登录，会自动提示改用「扫码 / 短信登录」。
