# 学习通巡检工具

把「登录 → 逐门课翻作业/考试/任务点 → 汇总成未完成清单」这一整套流程，固化成本地程序。
以后不用再找人对话排查，双击一个 bat 就跑完。

**它只读取数据，不会提交作业、不会修改课程内容、不会上传任何东西。**
所有请求都在你自己电脑上发出，账号密码也不经过本程序（登录在浏览器窗口里完成）。

---

## 一、快速开始

### 第 1 步：安装依赖（只做一次）

双击 **`安装依赖.bat`**。
它会自动找 Python 环境并把 `playwright`、`ddddocr`、`pillow` 装好。
如果提示缺 Python，就去 <https://www.python.org/downloads/> 装一个 3.10 以上版本，安装时记得勾选 **Add to PATH**。

### 第 2 步：查询

双击 **`一键查询.bat`**，浏览器会打开操作界面。在左边填入**账号（手机号）**和**密码**，
点 **「一键查询未完成事项」** 即可 —— 登录、扫描、出报告一条龙。

如果平台把密码登录拦下（提示密码错误，或要求点选 / 拖动验证），改用左边的
**「扫码 / 短信登录」**：会弹出一个浏览器窗口，用手机「学习通」APP 扫右侧二维码最省事。

登录成功后会话被保存到 `runtime/state.json`，**以后再查不用重新登录**。

### 第 3 步：看结果

扫描几十门课大约 1~2 分钟。结果直接显示在界面右侧（作业 / 考试 / 任务点分三块展示），
同时保存到 `输出` 文件夹，点「打开最新报告」可以看完整版。

## 二、界面说明

浏览器里打开的是一个本地控制台（地址 `http://127.0.0.1:8765`，**只监听本机，不对外网开放**）：

| 区域 / 按钮 | 作用 |
|---|---|
| **账号 / 密码** | 填学习通手机号与密码，配合「一键查询」使用 |
| **一键查询未完成事项** | 登录（如需要）+ 全量扫描，一步到位（主力功能） |
| 下钻到章节 | 勾选后未完成任务点会展开到具体章节（默认勾选） |
| **扫码 / 短信登录** | 密码登录被拦时用它：弹窗内扫码或短信验证码 |
| **环境自检** | 检查 Python、依赖、浏览器内核、登录态是否正常 |
| **只查最近 N 门课** | 填个数字，直接只查最近学过的 N 门——**不用先获取课程列表** |
| **获取课程列表** | 只读课程名单（约 10 秒），读完可以勾选要查哪几门 |
| **置顶已选的课** | 把勾上的课排到列表最上面并加分隔线，方便核对（不影响查询范围） |
| 打开最新报告 | 用系统默认程序打开 Markdown 报告 |
| 打开输出文件夹 | 定位到 `输出` 目录 |

界面右上角有两个页签：「查询结果」是把三类未完成项渲染成表格（作业还带直达链接），
「运行日志」是原始过程输出，出问题时看它。

扫描在后台线程里跑，**关掉浏览器标签页也不影响**（扫描会继续跑完）。

### 只想查其中几门课

不必每次都把所有课程扫一遍。有两种做法，按需要挑：

**做法 A —— 只查最近 N 门（最快）**

在左侧「**只查最近 N 门课**」里填个数字，直接点「一键查询」。
**不用先获取课程列表**，也省掉一次登录往返。顺序用的是学习通默认的「最近学习过的在前」，
所以取前 N 门就是最近学过的 N 门。只想快速看一眼最近的课、或先试试工具好不好用，用这个。
（输入框里按回车等于点查询。）

**做法 B —— 指定具体某几门（精确）**

1. 点 **「获取课程列表」**（约 10 秒，只读名单，不抓任何作业）
2. 左侧出现课程清单，**勾选**你要查的课（**勾上就生效**，不用再点确认）
3. 点「一键查询」，**只扫你勾的那几门**

两者同时用时**以勾选为准**，上方填的 N 会被忽略（界面会明确提示一句）。

几个细节：

- 做法 A 填的数 ≥ 课程总数时，按「查全部」处理，不标注范围（结果上本来就等价）。
- **一门都不勾、也没填 N = 照旧查全部**，所以不用这两个功能也完全不影响原来的用法。
- 课程面板上方有 **筛选框**（输「英语」就只剩名字带英语的），配合「全选 / 清空」可以批量操作——
  这两个按钮**只作用于当前筛选出来的可见项**，所以「搜『英语』→ 全选」就是选中所有英语课。
- 勾选后**没勾的课程会被压暗**，按钮右边直接显示 `✓ 已选中 N 门课`，一眼能看出这次查哪几门。
  改动勾选时这两处立刻跟着变，不需要点任何按钮。
- **「置顶已选的课」按钮**：把已勾选的课排到列表最上面，中间插一条
  `以下 N 门未勾选（本次不查）` 的分隔线，方便核对完再点查询。它**不影响查询范围**——
  勾选本来就已生效，这个按钮只改变显示顺序。改了勾选之后分隔线会自动撤掉（数量已过期）。
  和做法 A 的结果一样，区别是**你能看见勾了哪几门**、还能在此基础上手动加减。
  只想快就不填它，想看得清楚就用它。
- 只查了一部分课的报告会**明确标注范围**，而且会区分是哪种：
  勾选的写 `⚠️ 本次只检查了你勾选的 5 门课程（账号共 37 门）`，
  用做法 A 的写 `⚠️ 本次只检查了最近学习的 5 门课程（账号共 37 门）`。
  这句是必需的——否则你看到清单里没有别的课，很容易误以为都完成了，而事实是根本没查。
- 如果勾的课在当前名单里已经不存在（课程被删或改名），会**跳过并告警**；
  若一门都匹配不上，会直接报错而不是给你一份空报告。
- 「获取课程列表」是一次独立任务，**不支持暂停/停止**（它只有十来秒），
  这段时间暂停和停止按钮是灰的。

### 怎么中途暂停 / 停止

一轮全量扫描约 1~2 分钟，中途想缓一缓或者不扫了，随时可以：

| 按钮 | 行为 |
|---|---|
| **⏸ 暂停 / ▶ 继续** | 停在当前这门课结束时，进度全部保留；点继续，从下一门接着扫 |
| **■ 停止本次查询** | 结束扫描，**已扫完的部分照常出报告**，报告里标注「中止扫描，只检查了 N/M 门课」 |

两个动作都在**课程边界**生效，所以点下去之后最多等约一门课（10 秒左右）才真正停住——
这样不会把正在进行的网络请求撕断。只有扫描运行中，这两个按钮才可点。

实现上，扫描器（`chaoxing_scanner.py`）完全不知道界面的存在，它只在每门课开头调用一次
`checkpoint()`；界面通过 `set_control_hook(fn)` 注入回调，在回调里阻塞等 `PAUSE` 事件，
或用返回 `False` 表示中止。**CLI 模式不注入钩子，行为与以前完全一致。**

> **停止后有几秒不能开始新查询，这是正常的。**
> 这几秒在把结果写成报告，状态栏会显示「收尾中 · 正在生成报告」。
> 此时点查询会被明确拒绝并提示「上一个任务还在收尾」——等状态变回「已完成」再点即可。
> （早期版本在这里不给任何反馈，界面上看起来就像按钮失灵了，实际是后端回了 `409 busy` 被前端忽略。）

收尾阶段由 `scan()` 在生成报告前调用 `checkpoint('reporting')` 通知界面，
`_control_hook` 收到后把 `STATE['phase']` 置为 `finishing`，poll 接口再带给前端。

### 刷视频：把未完成的任务点视频挂后台（v2.7 起）

查询结果「三、未完成任务点」里，每门课的折叠条右侧有一个 **「刷视频」勾选框**：
勾上想刷的课（勾上即生效），再点本节顶部的 **「▶ 刷选中的课的视频」** 即可。

| 行为 | 说明 |
|---|---|
| 播放方式 | 在后台浏览器里**真实播放**：静音 + 2 倍速（可改 `config.json` 的 `brush_rate`），播到片尾为止 |
| 完成判定 | 播放器自己发心跳，平台看到的就是一次真实观看；章节列表里对应节点会翻绿 |
| 只刷视频 | 测验、作业、讨论等其它任务点**不会替你自动完成** |
| 暂停 / 停止 | 与查询共用同一对按钮：暂停会把当前视频一起暂停；停止保留已刷完的部分 |
| 进度 | 日志面板实时显示「第几门课 · 哪个节点 · 播放到几分几秒」 |

几点实话：

- **刷视频不是瞬时的**。视频有多长就要播多久（2 倍速减半），一门课 10 个 20 分钟的
  视频大约要 100 分钟。适合挂机，不适合救急。
- 偶尔视频会在中途**自动暂停**（平台插入的互动点），工具会自动点继续；
  若同一位置反复卡住（一般是弹题），会跳过并在日志里说明，需要你手动看那一个。
- 请求密度比查询高，**不建议一次勾十几门课连着刷**；工具已在课程之间留了间隔，
  但使用频率自己把握，账号安全第一。

### 怎么退出

| 方式 | 效果 |
|---|---|
| 网页左侧点「退出程序」 | 推荐。后台进程立即结束，端口释放 |
| 关掉那个黑色命令行窗口 | 等效，进程被终止 |
| 只关浏览器页面 | **不算退出**，程序仍在后台运行、端口仍被占用 |

端口占用不会导致下次打不开——`_pick_port()` 会自动往后找一个空闲端口（8765→8766→…）。
但它会让后台悄悄攒下几个 python 进程，所以还是点一下「退出程序」更干净。

实现上，`/api/quit` 先回包再异步调用 `httpd.shutdown()`（`shutdown()` 必须由 `serve_forever()` 之外的线程调用，
且不能先关连接、否则浏览器只会看到一个「网络错误」）。

## 三、输出文件

都在 `输出` 文件夹里：

| 文件 | 说明 |
|---|---|
| `学习通未完成清单.md` | 最新一次的报告（每次覆盖，方便直接看） |
| `学习通未完成清单_日期_时间.md` | 带时间戳的历史版本，不覆盖 |
| `学习通未完成清单_日期_时间.csv` | 表格版，可直接拖进 Excel / WPS |
| `记录/日期_时间.json` | 机器可读快照，用于和上次对比 |

报告分四部分：

1. **未完成作业** —— 带课程、作业名、状态、剩余时间，还有**直达链接**（点一下直接跳去做题）
2. **未完成考试**
3. **未完成任务点** —— 章节视频/资料的完成进度
4. **附录：全部课程状态总览** —— 37 门课逐一的作业/考试/任务点状态

另外每次扫描结束会自动和上一次快照对比，在日志里打印「新增了哪些、消失了哪些」，方便盯变化。

### 关于「未完成」的口径

学习通的作业状态有好几种：`未交`、`已完成`、`待批阅`、`已提交`、`已互评`、`待互评`。

**只有「未交」才是真正需要你动手的**；`待批阅`（老师还没改）、`待互评`（互评环节还没开）这些平台自己都算作已完成。
本工具按平台口径统计 —— 这也是为什么报告里的「未完成数」总能和课程页上「已完成/总数」的缺口对上。

## 四、命令行用法（可选）

不想用界面的话，直接在项目目录下执行：

```bat
python chaoxing_scanner.py doctor            :: 环境自检
python chaoxing_scanner.py selftest          :: 检测学习通是否改版（逐层验证解析规则）
python chaoxing_scanner.py login             :: 可见窗口登录
python chaoxing_scanner.py login --auto      :: 短信验证码全自动登录
python chaoxing_scanner.py list              :: 只列出课程名录（约 10 秒）
python chaoxing_scanner.py scan              :: 全量扫描
python chaoxing_scanner.py scan --limit 3    :: 只扫最近 3 门（最近学习过的在前）
python chaoxing_scanner.py scan --only 1001:c1,1002:c2   :: 只扫指定课程
python chaoxing_scanner.py scan --headed     :: 扫描时显示浏览器窗口（排查问题用）
python chaoxing_scanner.py brush 高等数学     :: 刷某门课未完成的任务点视频（名称部分匹配）
python chaoxing_scanner.py brush 高等数学 大学英语 --rate 1.5
python chaoxing_scanner.py gui               :: 打开网页控制台
```

`--only` 的值就是 `list` 打印出来的方括号里那串（`courseId:classId`），逗号分隔。
它优先于 `--limit`。

也可以直接双击 `首次登录.bat` / `检查环境.bat`。

**定时跑**：配合 Windows 任务计划程序，让它每天早上自动执行
`python chaoxing_scanner.py scan --no-open`，报告就会静静躺在 `输出` 里。

## 五、配置文件 `config.json`

首次运行会自动生成，需要的话手动改：

```json
{
  "chrome_path": "",      // 浏览器内核路径，留空 = 自动探测 / 首次自动下载
  "headless": true,       // 扫描时是否无头（不显示窗口）
  "course_delay": 1.2,    // 每门课之间的间隔秒数，别调太小
  "brush_rate": 2,        // 刷视频的播放倍速（1~16，默认 2；倍速是播放器认可的）
  "page_wait": 3.0,       // 页面加载后的额外等待秒数，网络慢就调大
  "max_courses": 0,       // 0 = 全部
  "open_report": true,    // 生成后自动打开报告
  "cpi": "",              // 学习通个人参数，自动获取
  "user_agent": ""        // 留空 = 按内核版本自动生成
}
```

## 六、学习通改版了怎么办（兼容性体检）

学习通是第三方平台，页面结构随时可能变。与其等一次全量扫描跑完才发现结果是空的，
不如先用体检把「工具依赖的每一层」逐层探一遍。

> 这个体检是**命令行功能，界面上不放入口**（普通使用者用不到，界面保持简洁）。
> 排查问题、或用户反馈「学习通更新后查不出东西」时，在命令行跑：

```bat
python chaoxing_scanner.py selftest
```

约半分钟，全程只读。它会依次验证：

| 层 | 检查项 | 失效后果 |
|---|---|---|
| L0 | 本地运行环境（内核 / 验证码识别） | 与平台无关，缺失只影响速度与自动登录 |
| L1 | 登录会话是否还有效 | 失效 → 重新登录即可，不是改版问题 |
| L2 | 课程列表能否解析（`a[href*=stucoursemiddle]`） | **最致命**：什么都查不到 |
| L3 | 卡片上的任务点进度 `x/y`（`.l-txt`） | 卡片概览丢失，「是否有缺口」判断失效 |
| L4 | 课程页左侧导航 `li[dataname]` | 作业/考试/章节的入口，读不到等于全抓不到 |
| L5 | 作业列表能否打开并解析（`/work/list`） | **核心功能**：作业漏查或全丢 |
| L6 | 考试列表（构造式 URL） | 考试漏查 |
| L7 | 章节下钻（`.chapter_item`） | 只影响任务点明细，作业/考试不受影响 |

结论分三档：✅ 通过 / ⚠️ 基本通过（有需留意项）/ ❌ 未通过（列出具体哪层断了）。
报告写到 `输出/兼容性体检_日期.md`，把它发给助手就能直接定位要改哪段解析规则。

**所以答案是**：学习通改版不等于工具报废 —— 大概率只有某一层需要改十几行选择器，
体检就是为了把「哪一层」变成确定的信息，而不是靠猜。

## 七、常见问题

**Q：提示「本地没有可用登录态，请先执行 login」**
登录态过期了。点界面上的「登录 / 更新登录态」重新登一次即可。
学习通的会话 cookie 是会话级的，浏览器被强杀或隔较久就会掉，属正常现象。

**Q：登录时跳出「请依次点击『X』『Y』『Z』」验证码**
在可见窗口里手动点，最省事。
如果用的是 `login --auto` 全自动模式：程序会先尝试自动识别，**识别不全时会自动打开一张带红框编号的图**，
你按提示顺序输入编号（比如 `3 1 4`）回车，程序替你点击 —— 大约 5 秒。
（实测这类书法体汉字机器识别率只有一半出头，所以留了这条兜底路径。）

**Q：第一次扫描时它在下什么东西？**
在自动下载 Chrome for Testing 内核（约 150MB，只下一次）。
因为这台机器没装 Chrome 也没装 Playwright 自带内核，需要一个能远程控制的浏览器。
下载完存在 `runtime/chrome`，以后一直复用。

**Q：学习通更新了，这工具还适用吗？**
命令行跑 `python chaoxing_scanner.py selftest` 做一次体检（约半分钟，只读），
它会逐层告诉你本工具依赖的页面结构是否还有效、断在哪一层、后果是什么。详见第六节。
体检通过却仍查不出结果，通常是登录过期（新解压的目录必须先登录一次）
或那几门课本身没有作业。

**Q：某几门课显示「无作业模块」**
不是漏抓。有些课（比如纯考试课、AI 助教课）本身就没有「作业」这个栏目，
程序会读课程页左侧导航来判定，导航里没有「作业」才会这么标。

**Q：有的课显示「⚠ 页面未加载」**
说明那几门课的页面当时没打开成功（网络抖动、平台临时拦截都会这样），
**它们的作业/考试结果是「没查到」而不是「没有」**。程序会自动重试一次
（撞了平台风控会先冷却 20 秒再试），重试仍失败就在报告和界面里明确标出来。
遇到这种情况稍后重新查询即可。

**Q：连续多门课都「页面未加载」怎么办**
这是触发平台风控了。程序现在会自我保护：连续 3 门失败就全局长冷却 45 秒
（还不行再冷却 90 秒），冷却期间点「停止」立即生效；两次冷却后仍连挂就
**主动中止扫描**，避免越撞越死。撞过风控后，本次扫描的课间间隔会全程
保持 2.5 秒不再提速。正确姿势：等 10 分钟以上再查，或先只勾选几门重要的课分批查。

**Q：扫描很慢 / 卡住**
默认每门课约 2~3 秒。几十门课一两分钟属正常；明显超出先看网络连通性，
再考虑调大 `config.json` 里的 `page_wait`（它是每页的等待上限，
页面就绪就走，填大只会让慢的时候多等）。课间间隔是自适应的：
一切正常时贴着下限走，哪门课页面出过状况就自动拉长，保护会话不被风控。

**Q：任务点能细到什么程度？**
现在会**自动下钻到章节**。只要某门课的任务点没做完，报告里就会列出该课每一章的
「待完成任务点」数量（例如「1.1 系统概述　待完成 2」），不用再自己点进去数。
这个下钻只对有缺口的课程执行，所以几乎不增加整体扫描时间。
（判定依据：章节节点带 `.catalog_jindu.catalog_tishi120` 即为未完成，
其中 `.catalog_points_yi` 的数字就是待完成数；已完成的节点没有这个元素。）

**Q：「刷视频」是什么原理？会不会封号？**
它在后台浏览器里**真实播放**视频（静音、2 倍速），播放器自己发心跳，
平台看到的就是一次正常观看——没有伪造任何请求。倍速用的是播放器自带的倍速档位。
风险与正常看视频相同，但**请求密度比手动观看高**，不建议一次勾太多门课连着刷；
刷视频时账号同时在别处登录看视频，也可能相互顶掉，自己安排好时间。

**Q：为什么有的视频刷不动？**
三种情况会跳过并在日志说明：① 视频中途有**弹题**（同一位置反复暂停）；
② 那个任务是测验/作业，不是视频——工具不替你答题；
③ 视频超长，超过了超时保护上限。这些都需要你手动看一遍。

## 九、原理（给好奇的人）

抓取链路全部走的是学习通网页自己用的接口，没有破解任何加密：

1. **课程列表** —— 打开 `i.chaoxing.com/base`，从内嵌 iframe 里取到 `mooc2-ans.chaoxing.com/visit/interaction`，
   滚动触发懒加载后，从课程卡片 `div.learnCourse` 里读出课程名、`courseId`、`classId`、任务点进度。
2. **作业列表** —— 每门课打开 `mooc1.chaoxing.com/visit/stucoursemiddle?...`，
   点左侧「作业」导航，读出它加载的 `mooc2/work/list` iframe 地址
   （这个地址里的 `enc`、`stuenc` 是**点击时动态生成**的，没法跨课程复用，所以必须逐个点）。
   列表每页 12 条，用 `.xl-nextPage` 翻页直到没有下一页，然后从 `.right-content` 里提取
   标题 / 状态 / 剩余时间 / 直达链接。
3. **考试列表** —— `mooc1.chaoxing.com/exam-ans/mooc2/exam/exam-list?courseid=..&clazzid=..&cpi=..`，
   这个地址可以直接构造，不用 `enc`。结构与作业列表一致。
4. **登录态** —— 登录后用 Playwright 的 `storage_state` 把 cookie（含会话级 cookie）整体导出，
   下次启动时注入回去，就能免登录。

### 为什么不用 agent-browser

之前那套排查用的是 `agent-browser` CLI。它的守护进程会随发起它的 shell 一起被回收，
导致「`open` 成功但 `get url` 变 about:blank」、登录态莫名丢失；而且 `| head` 这类管道会把它 SIGTERM 掉。
换成 Playwright 之后，浏览器生命周期完全在 Python 进程内，
上述问题从根上消失了 —— 更少组件，更少坑。

## 十、分发给别人用（免安装包）

本项目可以打包成一个**解压即用**的压缩包：同学拿到后不用装 Python、不用联网下内核，
解压双击就能用，账号密码只在他自己电脑上使用。

构建方式（在项目目录下执行）：

```bash
bash build/build_all.sh     # 组装 build/pkg：下载便携 Python + 装依赖 + 内置浏览器内核
python build/package.py     # 压缩成「学习通巡检工具.zip」
```

包内结构：

```
学习通巡检工具/
├── 1-一键查询.bat        ← 双击启动（GBK 编码，中文不乱码）
├── 使用说明.txt
├── app/                  ← 程序本体
│   ├── chaoxing_scanner.py
│   ├── webui.py
│   ├── captcha_solver.py
│   └── config.json       ← 已清掉个人 cpi
├── python/               ← 便携 Python 3.13 + playwright + pillow
└── chrome/               ← 内置浏览器内核（约 390MB）
```

⚠️ **分发前务必检查**：`app/runtime/` 里存的是**你自己的登录态**，`app/输出/` 里是你的报告，
都不应打包给别人。`build_all.sh` 已自动清理这两处，但手动打包时请留意。

界面上的「账号 / 密码」两个输入框就是给别人用的：
填完点「一键查询」即可；若平台拦下密码登录，会自动提示改用「扫码 / 短信登录」。
